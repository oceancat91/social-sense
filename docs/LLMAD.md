## 摘要

传统深度学习时间序列异常检测（TSAD）通常需要大量训练数据，且只输出异常点，缺少异常类型、告警等级和自然语言解释。LLMAD 提出一种无需时序微调、直接使用大语言模型进行异常检测的方法。

其核心由两部分组成：

1. **检索增强的时序上下文学习（Time-series ICL）**：从历史库分别检索与当前序列相似的正常样本和异常样本，帮助 LLM 建立正常/异常决策边界。
2. **异常检测思维链（AnoCoT）**：注入判断规则、异常类型定义和告警等级，并按“全局趋势 $\rightarrow$ 局部异常 $\rightarrow$ 复核”的专家流程完成判断。

LLMAD 同时输出：

- 异常点/异常区间；
- 异常类型；
- 告警等级；
- 可读的解释报告。

在 KPI、Yahoo、WSD 三个数据集上，LLMAD 的检测性能达到或接近先进深度学习方法，同时具备传统方法不具备的解释能力。

## 1. 研究动机

### 1.1 传统 TSAD 的不足

深度学习异常检测器的优势是准确，但存在两个关键问题：

1. **训练成本高**：依赖大量领域数据，数据收集与模型训练成本大；
2. **黑盒输出**：通常只返回异常位置，不说明：
   - 为什么异常；
   - 属于哪类异常；
   - 严重程度如何；
   - 用户应该如何理解和处理。

实际运维中，工程师还需要查历史数据、手册和领域规则，人工生成异常报告。

### 1.2 为什么尝试 LLM

论文认为 LLM 具备：

- 预训练阶段接触过数值和时间序列文本；
- 少样本上下文学习能力；
- 遵循自然语言领域规则的能力；
- 生成解释、类型和告警等级的能力；
- 无需对每个时序数据集重新训练。

但直接把数值序列交给 LLM 也存在困难：

- LLM 不天然擅长长数值序列；
- 不同数据集的“异常”定义不同；
- 缺少正常/异常边界时容易误报；
- 解释质量取决于模型是否真正理解数据背景。

## 2. 问题定义

单变量时间序列定义为：

$$
T=\{x_i\mid i\in[1,n]\}
$$

异常检测结果为：

$$
Y=\{y_i\mid i\in[1,n]\},\quad y_i\in\{0,1\}
$$

$y_i=0$ 表示正常，$y_i=1$ 表示异常。

论文将“可解释异常检测”拆为三部分：

1. **文本解释**：说明异常相对正常模式的偏离；
2. **异常类型**：如尖峰、下跌、水平漂移；
3. **告警等级**：Warning、Important、Urgent/Error。

## 3. LLMAD 总体流程

LLMAD 的输入输出流程如下：

1. 接收原始时间序列；
2. 数值缩放并添加索引；
3. 从历史数据库检索相似正常样本与异常样本；
4. 将领域判断规则、异常类型和告警等级注入提示词；
5. 使用 AnoCoT 引导模型依次检查全局、局部并复核；
6. 输出严格 JSON：
   - 是否异常；
   - 异常位置；
   - 异常类型；
   - 告警等级；
   - 结构化解释。

该方法不对基础 LLM 进行时间序列微调。

## 4. 时间序列预处理

### 4.1 数值缩放

为减少高精度小数带来的 token 开销，论文将数值映射为整数：

$$
x'_t=
\left\lfloor
1000\times\frac{x_t-b}{a}
\right\rceil
$$

其中：

- $a$ 为数据子集的 95% 上分位值；
- $b$ 基于 1% 和 99% 分位构造：

$$
b=\min x_t-\beta(\max x_t-\min x_t)
$$

这里的 $\min x_t$ 和 $\max x_t$ 分别采用 1% 与 99% 分位，以降低极端值影响。

### 4.2 值索引化

LLM 需要精确返回异常位置，因此输入被转换为：

```text
Index  Value
1      value_1
2      value_2
...
```

每个数值都有唯一索引，模型可直接返回异常点编号。

## 5. 时间序列上下文学习

### 5.1 正常库与异常库

LLMAD 维护两个历史数据库：

- 正常库 $\tilde{S}$：同数据源的正常时间序列；
- 异常库 $\hat{S}$：可从同数据集的不同子序列收集，以扩大异常类型覆盖。

当新序列到来时，分别检索：

- top-$K_1$ 个相似正常样本；
- top-$K_2$ 个相似异常样本。

同时提供正反示例的作用是建立更清楚的决策边界，而不是只展示“什么是异常”。

### 5.2 为什么不用普通文本向量检索

文本检索常使用 embedding + cosine similarity，但时间序列存在：

- 时间偏移；
- 局部拉伸/压缩；
- 相同形态出现速度不同。

因此论文使用 FastDTW，近似以线性复杂度对齐时序形态。

FastDTW 的递推近似为：

$$
D(i,j)\approx
\min\{D(i-1,j-1),D(i-1,j),D(i,j-1)\}+d(i,j)
$$

最终检索集合：

$$
\tilde{K}=
\left\{
\tilde{S}_i:
i\in\arg\min_{K_1}D_{\text{FastDTW}}(T,\tilde{S}_i)
\right\}
$$

$$
\hat{K}=
\left\{
\hat{S}_i:
i\in\arg\min_{K_2}D_{\text{FastDTW}}(T,\hat{S}_i)
\right\}
$$

### 5.3 ICL 的作用

检索到的正常/异常样本与待检测序列一起进入提示词，使 LLM 能够：

- 识别当前数据源的正常波动范围；
- 对比历史异常形态；
- 减少把普通波动误判为异常；
- 无需重新微调模型。

## 6. AnoCoT：异常检测专家流程

AnoCoT 包含两部分。

### 6.1 领域知识注入

注入内容包括：

1. **判断规则**：
   - 异常非常稀少；
   - 正常波动不应被误判；
   - 只有高置信情况才报警；
   - 异常区间应精确，不应无限扩张。
2. **异常类型定义**；
3. **告警等级定义**。

论文消融结果显示，删除判断规则造成的性能下降最大，说明明确“什么算异常”比只让模型自由推理更重要。

### 6.2 专家式分步判断

论文的三步流程：

1. **全局趋势评估**：判断整体基线、趋势和水平漂移；
2. **局部异常评估**：检查尖峰、下跌、短时偏离；
3. **复核**：考虑异常稀有性，排除季节性与普通波动造成的误报。

需要注意：在工程实现中，建议输出**结构化判定依据和证据引用**，而不是依赖或暴露模型不可验证的隐藏推理过程。

## 7. 可解释输出

### 7.1 异常解释

解释同时覆盖：

- 全局背景；
- 局部异常位置；
- 与历史正常模式的差异；
- 复核结论。

### 7.2 八类异常

| 异常类型 | 含义 |
|---|---|
| Single Spike | 单次尖峰，随后立即回归基线 |
| Single Dip | 单次下跌，随后立即回归基线 |
| Multiple Spikes | 多次离散尖峰 |
| Multiple Dips | 多次离散下跌 |
| Persistent Level Shift Up | 持续上移，不回归原基线 |
| Persistent Level Shift Down | 持续下移，不回归原基线 |
| Transient Level Shift Up | 短期上移，持续一段后回归 |
| Transient Level Shift Down | 短期下移，持续一段后回归 |

### 7.3 三档告警等级

| 告警等级 | 含义 |
|---|---|
| Warning | 可见偏离，但暂不关键，需持续观察 |
| Important | 可能演化为问题或造成系统压力 |
| Urgent/Error | 可能造成直接损害，需要立即处理 |

### 7.4 输出格式

论文要求严格 JSON，核心结构可概括为：

```json
{
  "briefExplanation": {
    "step1_global": "全局证据",
    "step2_local": "局部证据",
    "step3_reassess": "复核证据"
  },
  "is_anomaly": true,
  "anomalies": [117, 118, 119],
  "reason_for_anomaly_type": "类型依据",
  "anomaly_type": "TransientLevelShiftUp",
  "reason_for_alarm_level": "分级依据",
  "alarm_level": "Urgent/Error"
}
```

## 8. 实验设计

### 8.1 数据集

| 数据集 | 总点数 | 测试点数 | 异常比例 | 特点 |
|---|---:|---:|---:|---|
| KPI | 6,198,513 | 309,925 | 2.35% | 网站流量、CPU 等业务/系统指标 |
| Yahoo | 738,866 | 369,433 | 0.71% | 真实 + 合成，多种点/上下文异常 |
| WSD | 7,898,005 | 394,900 | 1.56% | Web 服务响应时间、错误率等 |

### 8.2 基线

包括传统、深度学习和 LLM 方法：

- SPOT；
- SRCNN；
- DONUT；
- VQRAE；
- AnoTransfer；
- Informer；
- TFAD；
- Anomaly Transformer；
- LLMTime。

LLMAD 主实验使用 GPT-4-1106-preview。

### 8.3 指标

- **Best F1**：在不同阈值中取最佳 F1，并采用 point adjustment；
- **Delayed F1**：若异常段首次识别延迟超过阈值，则视为漏检，更贴近在线告警场景。

论文设置：

- KPI、WSD 延迟阈值为 7；
- Yahoo 延迟阈值为 3。

## 9. 检测性能

| 方法 | KPI Best / Delayed F1 | WSD Best / Delayed F1 | Yahoo Best / Delayed F1 | 平均 Best / Delayed F1 |
|---|---|---|---|---|
| Informer | 0.859 / 0.715 | 0.534 / 0.370 | 0.707 / 0.671 | 0.700 / 0.585 |
| TFAD | 0.751 / 0.631 | 0.644 / 0.396 | **0.779 / 0.775** | 0.725 / **0.601** |
| Anomaly Transformer | **0.918** / 0.336 | 0.670 / 0.092 | 0.274 / 0.029 | 0.621 / 0.152 |
| LLMTime | 0.333 / 0.194 | 0.029 / 0.022 | 0.023 / 0.023 | 0.128 / 0.080 |
| LLMAD | 0.843 / **0.667** | **0.711 / 0.401** | 0.724 / 0.695 | **0.759 / 0.588** |

严谨解读：

- LLMAD 平均 Best F1 第一；
- 平均 Delayed F1 第二，略低于 TFAD；
- 并非每个数据集每项指标都第一；
- 与 LLMTime 的显著差异说明“直接用 LLM 预测”不够，检索式 ICL 和领域规则才是关键；
- Anomaly Transformer 虽有较高 Best F1，但 Delayed F1 很低，说明可能不能及时捕获异常段。

## 10. 消融实验

### 10.1 检索式 ICL

动态检索结果：

| ICL 配置 | WSD Best F1 | KPI Best F1 | Yahoo Best F1 |
|---|---:|---:|---:|
| 1 个异常例 | 0.548 | 0.756 | 0.602 |
| 1 个正常例 | 0.595 | 0.768 | 0.622 |
| 1 异常 + 1 正常 | 0.653 | 0.816 | 0.679 |
| 2 异常 + 1 正常 | 0.711 | **0.843** | **0.724** |
| 4 异常 + 1 正常 | **0.716** | 0.812 | 0.691 |

结论：

- 同时给正常和异常示例明显优于只给单类；
- 动态相似样本优于固定样本；
- 2 个异常 + 1 个正常是效果与 token 成本的良好折中；
- 示例继续增加后收益趋于饱和，甚至下降。

### 10.2 CoT 与 AnoCoT

论文报告：

- 标准 CoT 相比无 CoT，平均 Best F1 提升 9.5%；
- AnoCoT 在标准 CoT 基础上再提升 6.2%；
- 领域规则和专家步骤对判断一致性有明显帮助。

### 10.3 领域知识消融

| 配置 | WSD Best F1 | KPI Best F1 | Yahoo Best F1 |
|---|---:|---:|---:|
| 完整 LLMAD | 0.716 | 0.843 | 0.724 |
| 删除判断规则 | 0.423 | 0.652 | 0.555 |
| 删除异常类型 | 0.565 | 0.775 | 0.643 |
| 删除告警等级 | 0.696 | 0.810 | 0.700 |

判断规则最重要；类型与等级即使不直接决定异常点，也为模型提供任务语境和辅助约束。

### 10.4 基础模型影响

| 模型 | WSD Best F1 | KPI Best F1 | Yahoo Best F1 |
|---|---:|---:|---:|
| GPT-3.5 | 0.233 | 0.409 | 0.204 |
| Llama-3-70B | 0.360 | 0.701 | 0.490 |
| GPT-4 | **0.716** | **0.843** | **0.724** |

LLMAD 对基础模型的数值理解、规则遵循和复杂推断能力高度敏感，不能假设换成更小模型后仍保持同等效果。

## 11. 可解释性评估

由于原数据只有异常点标签，没有解释金标，论文邀请 5 名平均有 3 年经验的 DevOps 工程师，对 100 个异常案例进行人工评价。

### 11.1 解释质量

| 方法 | 有用性均值（1–5） | 可读性均值（1–3） | 有用性 HIP | 可读性 HIP |
|---|---:|---:|---:|---:|
| 标准 CoT | 3.58 | 2.57 | 56.08% | 94.61% |
| AnoCoT | **4.06** | **2.66** | **72.37%** | **97.11%** |

AnoCoT：

- 有用性平均提升 13.4%；
- 可读性平均提升 3.5%；
- 多数解释达到工程人员可接受水平。

### 11.2 异常类型分类

| 模型 | WSD Acc / Micro F1 | KPI Acc / Micro F1 | Yahoo Acc / Micro F1 |
|---|---|---|---|
| GPT-3.5 | 0.310 / 0.321 | 0.143 / 0.163 | 0.375 / 0.380 |
| Llama-3-70B | 0.379 / 0.400 | 0.286 / 0.250 | 0.600 / 0.552 |
| GPT-4 | **0.900 / 0.776** | **0.790 / 0.647** | **0.930 / 0.804** |

说明强模型能够依据文字定义完成异常类型分类，但该能力对模型规模和指令遵循能力高度敏感。

## 13. 局限

论文明确指出：

1. 相比传统模型，LLM 推理延迟和成本更高，不适合严格实时场景；
2. 结果高度依赖高质量提示词；
3. 领域知识最好由有经验的工程师提供；
4. 基础模型能力差异会显著影响性能。

进一步需要注意：

- Best F1 依赖阈值搜索和 point adjustment，可能高估实际部署表现；
- 解释自然流畅不等于事实正确，必须与原始数据和规则校验；
- FastDTW 大规模检索仍需索引、候选召回或缓存；
- 提示词中输入原始业务数据可能带来隐私和合规风险；
- 论文面向数值型单变量时序，不能直接代表文本舆情场景。

| 主控归纳 | 已有跨平台证据绑定与 CX 校准门 | `multiagent/master.py` |

项目已经具有 LLMAD 的三个雏形：

1. 可解释异常类型；
2. 历史知识检索；
3. 结构化生成与校准。

当前主要缺口是：

- 没有明确的“正常/异常正反示例库”；
- 异常没有风险等级；
- 提示词尚未形成舆情专用的结构化专家判断流程；
- 解释质量缺乏人工评测协议。

### 14.2 最值得迁移的部分

#### 高优先级：正常/异常双库检索

KnowledgeAugmentor 可扩展为：

- **正常传播样本**：普通热度波动、无实质立场翻转；
- **异常传播样本**：真实爆发、跨模态冲突、平台立场突变；
- 为当前窗口分别检索相似正常例和异常例。

时序形态可用 DTW/FastDTW，文本语义可用 embedding/BM25，最终形成混合检索分数。

#### 高优先级：异常风险分级

在 Skill3 的每条 anomaly 中增加：

```json
{
  "type": "sentiment_flip",
  "severity": "important",
  "score": 2.8,
  "evidence_ids": ["..."],
  "reason": "情绪均值由正转负且声量同步上升"
}
```

舆情分级不能照搬运维阈值，应综合：

- 异常分数；
- 声量和热度；
- 争议度；
- 偏向度；
- 跨平台一致/冲突；
- 证据完整性。

#### 中优先级：舆情版 AnoCoT

推荐将“思维链”改造成可校验的结构化报告流程：

1. **全局态势**：声量、热度、情绪、立场总体趋势；
2. **局部异常**：异常桶、异常类型和具体指标；
3. **跨模态/跨平台核验**：文本、互动、平台之间是否互相支持；
4. **反证与复核**：是否可能由空窗、采集偏差、刷屏造成；
5. **风险分级**：给出等级、不确定性和行动建议；
6. **证据引用**：所有断言绑定时间桶、平台和内容 ID。

这比要求模型输出不可验证的自由思维链更安全，也更容易被现有 G1–G7 / CX1–CX5 门禁校验。

#### 中优先级：解释质量人工评测

可借鉴论文的人工评价框架，定义：

- 有用性：解释是否帮助定位风险；
- 可读性：非技术用户能否理解；
- 忠实性：解释是否能由数据证据推出；
- 行动性：是否给出合理、不过度的建议；
- 证据覆盖率：断言中有多少绑定了证据 ID。

### 14.3 不能直接照搬

LLMAD 的对象是数值时序，Social Sense 的对象是：

- 文本；
- 互动指标；
- 立场分布；
- 多平台时序；
- 圈层文化与平台黑话。

因此：

- “尖峰/下跌”只能覆盖数值异常，无法覆盖讽刺、议题漂移、立场反转；
- 正常/异常示例不能只按 FastDTW 检索，还需语义与平台条件；
- 运维告警等级不能直接映射社会风险；
- 舆情事实判断必须防止 LLM 将高热度误写成真实事件已被证实；
- 多平台差异可能来自平台人口结构和推荐机制，不应自动视为异常。

## 15. 对项目创新叙事的提升

LLMAD 可以强化：

- **学术创新**：把 Skill3 的量化异常与 Skill5 的可解释风险判型结合，形成“检测—解释—复核”闭环；
- **工程创新**：异常示例库由多个平台 Agent 共享，主控可比较各平台异常类型与等级；
- **社会价值**：用户不仅看到“指数上升”，还能理解在哪个平台、何时、因何种立场/情绪变化形成风险，并看到证据与不确定性。

## 16. 推荐最小实施路线

1. 在 `detectors.py` 为每条异常新增 `severity` 与 `reason`；
2. 在 KnowledgeAugmentor 中落盘人工确认的正常/异常案例；
3. 先实现 1 个正常例 + 2 个异常例的动态检索；
4. 在 `prompts.py` 中加入结构化五步分析字段，而不是自由文本思维链；
5. 在校准门中增加：
   - 等级与异常分数一致；
   - 每个异常断言有 evidence ID；
   - 空数据和低置信度不得输出高等级；
6. 用人工标注的小型舆情异常集评估：
   - Event-F1 / Delayed F1；
   - 异常类型 Micro-F1；
   - 解释忠实性和有用性；
7. 保留无 LLM 的确定性降级路径。

## 17. 论文对项目的核心启示

LLMAD 最重要的启示不是“让 LLM 直接替代异常检测器”，而是：

> **让确定性检测器提供候选异常，让历史正反例和领域规则帮助 LLM 判型、分级与解释，再用规则门禁校验输出。**

这与 Social Sense 当前的 Skill3 $\rightarrow$ Skill4 $\rightarrow$ Skill5/6 架构天然匹配，也比完全依赖 LLM 直接读取长时序更可靠。
