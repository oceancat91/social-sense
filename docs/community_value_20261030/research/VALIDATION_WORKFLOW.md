# 从社区应用价值到可验证研究

适用于本轮新增场景，不改写仓库业务功能，也不把以下任务写为已完成。

1. 建立小规模梗事件样本：保存内容、公开作者标识、发布时间、采集时间、原链接和可见引用。真实身份不是采集目标。
2. 将官方素材、玩家原创、同源改写、转载和无关内容分别标注；对分歧样本保存理由，不能只靠关键词或相似图判定来源。
3. 复用 `multiagent/contract.py`、`align.py` 的观测契约及时间对齐。缺失保留，不能把平台内标准化当成语义同源判断。
4. 建立首发候选与关系边：直接引用、作者明确署名和仅有时间先后三类分开。最早采到不自动等于真正源头。
5. 设计同源识别与传播关系基线。先评价准确率、召回率、错误归因与人工复核耗时，再决定是否增加图模型或多模态模型。
6. 用 G/CX 规则校准报告的统计和引用结构；对梗义、反讽和来源支持关系做人工审核。规则通过不替代内容核验。
7. 预测仍遵循原时间切分、训练段归一化和固定验证阈值。新增社区样本须单独评估，不能沿用已有数据的65.53%作为该场景成绩。
8. 研究回应前后互动：预先定义时间窗及有效二创、反馈质量、误读案例等指标，记录版本更新、活动投放和创作者曝光等混杂因素；未有可信对照时只报告关联。
9. 试用先检验“来源证据是否更易查”“复核是否省时”，再评估工具或专题报告的应用方式；不预设营收、付费意愿或商业领先结论。

社区维护目标是呈现真实诉求、减少误读和支持创作认可，不以隐藏批评或定向操纵玩家观点作为产品成效。
