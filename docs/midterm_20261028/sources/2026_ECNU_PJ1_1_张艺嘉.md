1. 项目目标与需求解释
系统实现一个可运行的简化在线问卷系统：注册登录后创建自己的问卷，配置单选、多选、文本、数字题及约束
与条件跳转，发布分享链接，由登录用户填写并保存答卷，创建者查看整卷、单题与原始内容统计。核心目标是
把配置与答案组织成 MongoDB 文档，并证明校验、权限、多人提交与统计口径在实际系统中一致。
课程硬要求为 MongoDB 持久化、不使用关系数据库或现成问卷框架、上述业务功能、明确测试步骤与真实 AI
记录；语言、框架与简单前端可自行选择，不把本项目选的 Python/FastAPI、单节点副本集或资源上限冒充教师
指定方案。原文未定义匿名、重复与重试、空答、可达必答和截止并发语义，S1 先采纳项目解释再实现：填写仍
需登录；匿名只向创建者隐藏账号；默认每账号每卷一次，可显式允许多次；每次成功提交独立保存，提交前不
自动保存草稿；只检查可达必答题；发布后冻结配置；受理时刻须严格早于截止。这些是已记录的项目决定，不
声称经教师另行确认。映射见 REQUIREMENTS.md，决策见 DECISIONS.md。
2. 系统设计与使用流程
三层结构：浏览器（原生 HTML/CSS/JavaScript，无前端框架）→ FastAPI（认证、UTF-8 JSON、输入与请求
边界）→ MongoDB（账号、会话、问卷、发布快照、答卷）。服务端负责所有权、生命周期、校验与路径、提
交事务和统计；浏览器只做交互辅助，最终保存一律以服务端发布配置重新校验。
模块 职责
main.py / models.py 路由、错误处理、请求大小与 Origin 边界；请求字段白名单
security.py / service.py scrypt 哈希与会话鉴权；本人问卷、revision 编辑、发布/截止/关闭
questions.py 配置检查、答案校验、路径求值
submissions.py / statistics.py幂等回执与事务提交；整卷/单题统计与明细白名单
db.py / config.py Schema、索引、配置

## 第 4 页

创建者：注册登录 → 新建草稿（标题、说明、匿名与重复开关）→ 加题目与约束、配跳转 → 保存并发布。每次
编辑携带 revision，过期版本不能覆盖新编辑；发布前重查配置，发布后只允许调整生命周期，不重写题目与策
略。分享链接稳定；截止按 UTC 保存、按北京时间显示；关闭后不重开；其他账号即使知道问卷 ID 也无法管理
或读取结果。
填写者：登录后打开分享链接，逐题作答，前端按 /next 返回的服务端下一题与路径推进；错误定位到题目，回
改清除后续答案；完成后先核对再提交，收到回执才算保存。提交结果不确定时保留同一编号与答案快照重试，
不把网络重试误当再次填写；允许重复时新一轮才生成新编号。
安全边界：密码只存独立随机盐的 scrypt 摘要；会话 token 只存服务端摘要，过期每次请求显式检查，TTL 仅负
责后台清理；Cookie 为 HttpOnly + SameSite=Strict，本地 HTTP 关闭 Secure，不把实验配置当作公网方案；
管理查询联合过滤 owner_id，越权 404；错误响应不回显密码、Cookie、连接串或堆栈；请求体读取时限 1
MiB。
3. MongoDB设计与取舍
访问模式决定集合边界：账号按规范化用户名登录；用户按拥有者列问卷；填写者按分享码读一个固定发布卷；
一次提交写一份完整答卷；创建者按问卷与版本读答卷生成统计。因此用五个集合，而不是把全部数据混在一
起，也不机械照搬关系表的逐字段拆分。
集合 关键字段与设计意图
users 稳定字符串 ID、用户名、trim+casefold 的 username_key（唯一）、密码哈希、注册时间、
schema_version
sessions token 摘要、user_id、创建/过期时间、schema_version；账号与会话分离，可撤销单次会话，认证不
依赖 TTL 即时删除
surveys 拥有者、分享码、标题/说明、匿名与重复策略、状态、UTC 截止、revision、gate_seq、发布版本；
草稿题目与规则内嵌 draft，便于整体编辑与条件更新
survey_versionssurvey_id、version、questions、rules、时间、schema_version；题目/选项/约束/顺序/跳转作为不
可变快照整体读取
responses 每次成功提交一个文档：问卷与版本、私有 respondent_id、request_id、内容摘要、answers、
path、匿名与判重策略、提交时间；持续增长的答卷不嵌入问卷
取舍：题目与选项在快照内嵌，匹配“整卷读取”的访问模式；答卷保留 version 与 path 是解释当次填写所需的
有意冗余，不另存可能失真的统计副本；选项按 ID 而非标签关联，题目 ID 只接受安全字符；单文档按实际
BSON 限制 1 MiB，并限制每卷 100 题、每题 50 选项、500 条规则、单条文本 10000 码点（项目资源边界，不
是课程容量结论）。
索引与一致性：username_key、share_code、survey_id+version 分别唯一；owner_id+created_at 服务本人列
表；survey_id+version 服务统计；survey_id+respondent_id+request_id 保证同次请求唯一（网络重试幂
等）；survey_id+respondent_id 的部分唯一索引只覆盖 single_submission=true，从而禁止一次模式重复，又
不阻碍允许重复的模式；expires_at 为 TTL。两类唯一约束不能互相代替，先查询再插入也不能替代数据库约
束。逐索引与查询的对应关系见 DATABASE.md。
为什么这样设计：字段校验只负责文档形状，题型约束、跳转图、所有权与状态转换仍在应用层校验，不因用了
$jsonSchema 就省略业务验证。为什么适合 MongoDB：题目类型与约束多样、整卷配置整体读取、答卷字段随
题 ID 变化，适合内嵌文档加独立答卷的组织方式。为什么不用关系式结构：本设计不为模仿关系表而拆分题目与
选项，减少与访问模式无关的关联操作；这不意味着关系数据库无法实现问卷系统，MongoDB 的多文档业务同
样需要事务与索引来保证提交/关闭的一致性。

4. 配置跳转设计
跳转是一组持久化规则，形如 {"source":"q1","op":"eq","value":"no","target":"q3","priority":10}（解释
格式的构造样例，不是实际浏览器问卷 ID 或测试输出）。解释器从发布快照读规则，代码中没有“第 1 题选 A
固定跳第 5 题”的分支。
来源与算子：单选仅 eq（值须为合法选项）；多选 any（与选中项有交集）、all（非空条件集合全部包含
于选中项）；数字 eq/lt/lte/gt/gte（值须为有限数值）。
优先级：同一来源题 priority 唯一，按数值升序首条命中；不同来源可复用同一数值；无命中按题目顺序继
续，末题正常结束。
跳转目标：必须存在于同卷且严格位于来源之后；发布前拒绝自环、回跳、陌生目标、重复题 ID 与不支持的
算子。只允许向后是本期确定的项目选择，可直接排除环路。
运行时：从首题遍历，对每个可达答案先校验再求条件。partial=True 把缺键视为未回答并停在该题；显式
null 表示主动跳过可选题并可前进。返回的 path 含当前待答题，answers 保留已访问题的 null。
提交时：重新完整遍历，可选缺失规范为空、必答缺失拒绝，路径外或未知答案拒绝，持久化省略空值但保留
实际访问路径，从而防止客户端伪造路径绕过要求。
5. 统一校验设计
配置保存、发布复验、逐题预检与最终提交共用同一套语义；运行期一律以服务端发布配置为准，浏览器提示只
是交互辅助。
题型 服务端校验口径
单选 只能是已定义选项 ID，必答不能空
多选 合法且无重复 ID 的列表，先拒重复再查 min/max/exact，合法值按配置顺序规范化
文本 保留原文，长度按 Unicode 码点（非视觉字素）；全空白视为空
数字 必须有限 int/float 且不是 bool，不把数字字符串隐式转数值；上下界包含；整数题接受数学整数 1.0 规范为 1，不
截断 1.5，0 是有效值
空值仅指 null、单选空串、多选空列表、文本空白等明确情形，不把任意错误类型当空；可选题空答跳过非空数
量/长度/范围限制，非空即执行全部约束。非法值返回 422 并尽量带 question_id；不可 BSON 编码字符串、超
BSON 整数与非有限 JSON 数值同样拒绝，不留给数据库产生不可解释的成功结果。
配置本身检查类型、字段白名单、min≤max、非负整数计数、exact 相容且不超过选项数；S4 补充必答可满足性
（必答多选 max/exact=0、必答文本 max_length=0、整数上下界之间无整数均拒绝），先登记 D06 与测试预期
再实施，未按测试结果降低约束。

7. 统计与匿名设计
统计先校验 owner，再在 snapshot 事务中读取当前发布配置与该 survey_id/version 的答卷，一次查询取固定
答卷集后在 Python 计算，不维护文件业务库或持久化统计副本。整卷给提交数与去重人数及各题结果，单题同
口径；选择题给次数与人数，文本与数字给原始值数组，数字另给均值；零有效数字返回 null，空答与路径跳过
不补零，关闭后已有结果仍可读。
手算夹具（两名填写者、三份经 API 成功提交的答卷）：结果为 3 份 2 人；单选 A 2 次 1 人、B 1 次 1 人；多选
X 2 次 1 人、Y 2 次 2 人；文本甲/乙/丙；数字 2 份 2 人、值 10/20、均值 15；每个单题结果与整卷对应项相
等。均值实现按“先除后 fsum”，并在诊断出最大有限 double 仍可能溢出后加入缩放回退，另以真实 API 追加
最大正、最大负与大数抵消三组回归。
匿名结果由服务端白名单生成，不返回 respondent_id、request_id、payload_hash 或密码/会话字段，非匿名
明细才额外返回 username；数据库保留的私有身份用于判重与去重人数，不声称无法追溯。测试同时检查字段
名、实际私有值与匿名用户名未出现在序列化结果中，而非只看页面是否隐藏。
