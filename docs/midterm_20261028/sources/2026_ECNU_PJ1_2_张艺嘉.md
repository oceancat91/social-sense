2.1 系统设计
服务端仍是 FastAPI + PyMongo 的单体应用：survey_app/library.py 承载题目库的领域逻辑（版本、共享、
题库、链接），main.py 只做路由与鉴权，db.py 负责集合校验器与索引，前端是 /library 一个原生页面加
library.js。一阶段的问卷、填写、发布与统计服务保持不变，题目库只通过 import_into_survey 与
revise_in_survey 两个入口与问卷交互。

## 第 5 页

2.2 跳转设计
二阶段不改跳转模型：规则仍以题目 id 作键，存放在问卷数据里，发布后随快照冻结。唯一相关的处理是 fork
时重写规则引用——复制题目生成新 id 后，把规则里的 source/target 从旧 id 映射到新 id，避免副本指向原
题；该行为有 test_fork_with_rules_rewrites_the_reference 覆盖。
2.3 校验设计
校验分三层：请求模型（models.py）校验字段类型、长度与枚举；领域层校验业务不变量（版本归属、权限、归
档状态、题库钉版、链接时效、重复共享），失败返回带错误码的 404/409/410；数据库层用集合校验器与唯一
索引兜底。前端只做输入提示，不作为判定依据，因此直接调用 API 也无法绕过规则。题目自身的 validation
（必答、数值范围等）随版本保存，问卷填写时按快照里的规则执行。
3. 版本与冻结语义
1. 已发布问卷的题目不可改；编辑生成新版本，旧问卷仍引用旧版本。
2. 版本只追加：恢复历史版本会生成新版本并记录 restored_from。
3. 不同问卷可分别钉住同一题的不同版本，usage 按版本分组，能看出谁还在用旧版。
4. 共享与 限权
所有者可建版本、恢复、共享、归档、管理题库；被共享者可以 import 与 fork，但不能改原题。usage 与跨问
卷统计对非所有者只展示其本人问卷，另有 other_surveys 计数。分享链接面向任意登录用户：预览返回标题与
所有者名；领取写入 question_shares 且幂等，重复领取不消耗次数；过期或次数用尽返回 410，吊销或归档返
回 404。
5. 与题库 统计
导入优先级为“显式版本 → 题库钉版 → 当前版本”。归档题目不能新加入问卷或题库，已加入的草稿与已发布
快照不受影响。跨问卷统计支持单选占比、数字均值与文本样本，可用 ?limit=N（默认 200、上限 500）限制扫
描范围，被截断时返回 truncated=true。
6. 面流程页
/library 一页完成：左侧新建题目与题库，右侧“我的题目 / 共享给我的”、搜索、详情面板（版本历史、被哪
些问卷使用、共享、 修改题目、加 入问卷、跨问卷统计）。 详情里的“恢复此版本”“加 入问卷” 直接调用
API，失败时提示，不静默失败。
