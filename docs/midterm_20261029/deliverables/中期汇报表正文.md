# 目标与内容

本项目围绕多源社交媒体舆情分析中“跨平台口径难统一、生成结论难追证、未来趋势难验证”的问题，研究并实现 SocialSense 舆情溯源与辅助预测系统。项目以创新训练为定位，重点考察研究方法、系统实现、实验可复核性及学生科研能力提升，服务于公共议题观察、传播研究和辅助研判。
立项研究内容包括五个方面：一是建立多平台数据接入、字段映射、清洗和时间标准化流程，保留来源与缺失信息；二是研究平台间立场、情绪及热度差异，逐步实现同一事件的跨平台语义对齐；三是探索传播关系建模、关键节点识别及路径回溯；四是研究文本信息与热度时序协同的多步预测方法，评估方向判断、尖峰识别与数值误差；五是开发可交互分析终端及带证据引用的报告生成流程。
中期工作聚焦“数据契约—分析校准—辅助预测—交互展示”的原型闭环：形成可检查的数据接口和规则约束，完成四分量预测模型及数值推理包验证，形成可运行的三维档案终端，并梳理尚未完成的传播图和语义对齐任务。结题阶段拟补充跨话题验证、用户试用与成果材料；软件著作权和论文成果以正式回执为准，不将计划事项列为已取得成果。

# 研究进展和当前成果

（一）形成分层原型及统一数据契约
项目已建立 Flask 后端、TypeScript/Vite/Three.js 前端、单平台分析与多平台融合模块，并设置多平台适配接口。单平台以文本、时序和元数据组织输入，通过 PlatformReport 向多平台层传递结果。现有接口与样例能够支撑原型分析；六平台适配能力不等于六平台均已完成稳定在线采集。预测实验所用数据单独登记为 2023年1月1日至2026年8月31日的1339个日度观测，避免与其他采集批次混用。
（二）建立单平台六阶段分析与证据校准流程
单平台链路依次完成采集清洗、立场画像、文本与时序分析、知识检索补充、结论生成和规则校准；编排支持 LangGraph，并保留线性执行路径。G1—G7规则分别检查声量趋势、情绪趋势、主导立场、引用标识、年份与百分比边界、空数据表述以及风险等级与分析证据的一致性。外部检索作为背景补充，不能替代本平台观测；规则通过也不等于事实正确，关键判断仍需人工复核。目前文本侧采用TF-IDF等特征，尚不能表述为已完成图像、视频联合编码。
（三）实现跨平台统计对齐与受约束汇总
对齐器对各平台时间轴作外连接，保留缺失值，并在平台内标准化声量；融合器计算立场分布的Jensen-Shannon散度、情绪均值极差和声量相关性。主控通过CX1—CX5核查平台覆盖、分歧表述、引用平台、断言绑定与空窗处理。现有加权得分用于提示平台差异，尚未以用户互动网络验证回音室效应，也不能据此判定传播因果；向量级事件聚类与传播图溯源仍在后续计划中。
（四）完成四分量预测模型与可复核评估
模型将输入拆分为趋势T、季节S、冲击C和剩余项R，分别采用线性、PatchCNN、稀疏事件和轻量状态空间编码，再以稀疏混合专家融合并输出预测增量。EMA含可学习平滑参数；R是代数剩余项；路由器接收四路数值表征。完整模型含可选文本增量路径，本次部署验证采用关闭文本的数值路径。
以过去28天预测未来6天，按时间划分训练937天、验证135天、测试267天；测试形成262个窗口。2026年10月19日独立验证记录显示，数值路径方向准确率65.53%（235个非平坦窗口），尖峰AUC为0.610；固定验证集阈值下，召回率39.39%、精确率38.24%。标准化log1p空间MSE为1.889，高于持续值基线1.525约23.87%，说明数值拟合与预警可用性仍有改进空间。重叠窗口并非独立样本，现阶段不作显著性或跨场景泛化结论。
（五）完成数值权重导出与交互原型
数值推理包含49373个参数，文件约242.17KiB；完整检查点约477.39MiB。CPU、with_text=False条件下，262个测试窗口的导出前后最大预测差为0，验证了该数值路径的一致性，不能外推为完整文本路径等价或服务器内存表现。前端已实现三维档案浏览、详情和检索等交互；本次留存仓库本地运行截图，展示内置档案数据。下一步需补齐线上服务联调、低配置运行测量与用户试用记录。
阶段产出包括原型代码、模型权重与验证记录、文献阅读及证据索引、研究工作流和规范约束文档。传播溯源、跨平台语义对齐和成果申报材料尚需继续完善。

# 创新特色

项目特色体现在面向舆情任务的系统组合与可核验设计，现阶段定位为方法探索和工程实现，不主张单个基础算法首创。
1. 将证据约束贯穿多平台分析。以PlatformReport统一模块接口，将G1—G7单平台规则与CX1—CX5跨平台规则串联，使生成结论能够回查观测、引用和风险依据。其价值在于暴露不一致和证据缺口，而非宣称消除模型幻觉。
2. 面向突发热度设计分量专属预测路径。在已有分解预测、PatchCNN及选择性状态空间思想基础上，构建T/S/C/R四分量编码与稀疏专家融合，区分缓慢趋势、周期和冲击信息；其相对优势仍需消融、简单基线和跨话题实验验证。
3. 将可部署性纳入研究评价。导出约242.17KiB的数值推理包并验证指定路径一致性，降低权重分发成本；同时公开MSE未优于持续值基线的结果，将文件体积、运行资源、预测质量分别评价。
4. 以交互档案连接研究与应用。将平台来源、观测范围、结论和研究记录组织到可浏览界面，为人工复核提供入口。平台差异得分仅作为探索线索，后续以事件标注和互动网络检验解释的有效性。

# 研究心得

（一）研究问题需要通过可检验的指标表达
立项时，我们更多关注功能是否齐全。随着数据、模型和前端逐步联调，我们认识到，原型能够运行与研究结论成立是两件不同的事。跨平台结果必须说明平台覆盖和缺失情况，预测结果必须说明时间切分、目标空间和评价规则，截图也必须说明来自本地数据还是实时服务。把这些口径固定下来，是从完成课程式功能转向开展研究的重要一步。
（二）如实面对负结果，并保留改进依据
当前模型具备一定方向判别能力，但MSE仍高于持续值基线。我们不能用单一有利指标替代完整评估，也不能将尚未验证的原因写成结论。下一步需要分别检查冲击处理、幅度恢复、文本信号和专家融合的贡献，通过统一切分下的基线及消融实验定位问题。只有在误报成本、召回率和实际使用需求同时明确后，才能讨论预警的应用价值。
（三）可复现性依赖细节和边界
完整检查点与数值推理包的等价性检验，使我们进一步理解：模型名称、参数规模和文件体积都不能代替行为验证。本次数值路径一致，并不代表关闭文本与启用文本具有相同功能，也不代表低配置服务器已经通过性能验收。类似地，代码中的模块名称不能直接当作成果描述，文本特征分析不应被扩大为完整多模态感知。保持文档与实际调用路径一致，是科研记录应承担的责任。
（四）统一接口改善协作，明确责任保障进度
五位成员围绕总体架构、数据质量、预测评估、传播研究和交互实现分工。统一字段、时间格式、缺失值约定及报告结构，能够减少联调时的重复解释。后续将用“任务—负责人—证据文件—验收条件”的方式管理进度，对未达到验收条件的任务明确标注进行中，避免仅凭代码存在就判断研究已完成。
（五）调整研究节奏，优先补齐关键证据
目前传播关系数据与跨平台事件标注仍不足，相关模块进度落后于原计划。我们将先建立可人工核查的小规模样本和简单基线，再推进图模型与复杂融合；同时尽早记录部署资源、失败样例和用户反馈。文献阅读、过程留痕和负结果分析将与开发同步开展，使最终成果既能展示，也能被复核和解释。
