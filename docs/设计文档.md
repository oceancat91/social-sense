# Social Sense 系统设计文档

## 1. 系统架构设计

### 1.1 整体架构

系统采用前后端分离的 B/S 架构，分为以下几个层次：

```
┌────────────────────────────────────────────┐
│                 用户层                      │
│         浏览器 / 移动端                      │
├────────────────────────────────────────────┤
│                 前端层                      │
│     React/Vue + ECharts 可视化              │
├────────────────────────────────────────────┤
│                 接口层                      │
│        RESTful API / WebSocket             │
├────────────────────────────────────────────┤
│                 业务层                      │
│   用户管理 | 数据采集 | 分析引擎 | 预警服务   │
├────────────────────────────────────────────┤
│                 数据层                      │
│     MySQL | Redis | MongoDB (可选)          │
└────────────────────────────────────────────┘
```

### 1.2 模块划分

- **用户模块**：注册、登录、权限管理
- **采集模块**：爬虫管理、数据清洗、数据存储
- **分析模块**：NLP 处理、情感分析、热点发现
- **展示模块**：数据看板、图表渲染、报告导出
- **预警模块**：阈值监控、消息推送

## 2. 数据库设计

### 2.1 核心数据表

#### 用户表 (users)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT (PK) | 主键 |
| username | VARCHAR(50) | 用户名 |
| email | VARCHAR(100) | 邮箱 |
| password_hash | VARCHAR(255) | 密码哈希 |
| role | VARCHAR(20) | 角色 |
| created_at | DATETIME | 创建时间 |

#### 监控任务表 (monitor_tasks)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT (PK) | 主键 |
| user_id | INT (FK) | 所属用户 |
| keywords | TEXT | 监控关键词 |
| platform | VARCHAR(50) | 目标平台，all 表示全平台 |
| status | VARCHAR(20) | 任务状态（active/collecting/paused） |
| data_count | INT | 已采集数据量 |
| created_at | DATETIME | 创建时间 |

#### 舆情数据表 (sentiment_data)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INT (PK) | 主键 |
| task_id | INT (FK) | 关联任务 |
| platform | VARCHAR(20) | 平台标识（6 大平台） |
| content_type | VARCHAR(20) | 内容类型（post/comment/video） |
| content | TEXT | 清洗后的内容文本 |
| content_hash | VARCHAR(64) | 去重哈希（与 task_id 联合唯一） |
| source | VARCHAR(100) | 来源 |
| author | VARCHAR(100) | 作者 |
| url | VARCHAR(255) | 原文链接 |
| sentiment | VARCHAR(20) | 情感标签（positive/negative/neutral） |
| score | FLOAT | 情感得分 [-1, 1] |
| keywords | VARCHAR(500) | 提取的关键词（JSON） |
| like_count | INT | 点赞数 |
| comment_count | INT | 评论数 |
| share_count | INT | 转发数 |
| published_at | DATETIME | 发布时间 |
| collected_at | DATETIME | 采集时间 |

## 3. 数据处理管道

```
采集（CrawlerService）
   │  多平台原始数据（模拟源 / 预留真实采集器）
   ▼
清洗（CleaningService）
   │  去 HTML/URL/@提及 → 标准化 → 哈希去重 → 有效性过滤
   ▼
NLP 分析（SentimentService）
   │  大模型情感分类（LLM_API_KEY 配置后启用，支持反讽/隐含情绪）
   │  次选：预训练模型情感分类（置信度阈值判中性）
   │  兜底：词典分析；+ jieba TF-IDF 关键词提取
   ▼
入库（SentimentData）
   │  task_id + content_hash 联合唯一约束，支持幂等重跑
   ▼
多维分析 API → 可视化看板
```

管道由 `PipelineService` 统一编排，任务创建后自动在后台线程执行，支持手动重跑与幂等去重。
