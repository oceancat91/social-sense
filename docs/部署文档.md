# Social Sense 部署指南

## 部署形态

| 形态 | 入口 | 适用场景 |
| --- | --- | --- |
| Docker Compose | `deploy/docker-compose.yml` | 单机快速部署；分析台位于 `/app/` |
| 宿主机 Nginx | `deploy/nginx-social-sense.conf` | 正式域名；Landing 位于 `/`，分析台位于 `/app/` |
| Render | `deploy/render.yaml` | 仅部署后端 API |

以下步骤以腾讯云 Ubuntu 22.04 上的 Docker Compose 为例。

配置文件已归入子目录。以下 Compose 命令均在仓库根目录执行；配置中的构建目录与绑定挂载以 `deploy/` 为基准，项目名固定为 `social-sense`，沿用默认部署的数据卷。

使用 Render Blueprint 时，将控制台的 **Blueprint Path** 设置为 `deploy/render.yaml`（现有 Blueprint 也需更新）。其中 `rootDir: backend` 仍指向仓库内的后端目录。自定义路径与现有 Blueprint 的修改方式见 [Render 官方说明](https://render.com/changelog/blueprints-now-support-custom-filenames-and-paths)。

## Docker Compose 方案概览

| 部分 | 方案 | 说明 |
|------|------|------|
| 服务器 | 腾讯云轻量应用服务器 | 2核2G / Ubuntu 22.04 |
| 前端 | Nginx（容器内） | 端口 80；`/app/` 提供分析台，`/api/` 反向代理到后端 |
| 后端 | Flask + Gunicorn（容器内） | 内置 MySQL 健康等待 |
| 多 Agent 引擎 | agent/ + multiagent/（只读挂载进后端容器） | 跨平台对齐·融合·茧房指数 |
| 数据库 | MySQL 8.0（容器内） | utf8mb4 编码，数据持久化 |
| 缓存 | Redis 7（容器内） | 会话缓存 |
| 部署方式 | Docker Compose | 一条命令全部拉起 |

## 部署步骤

### 第一步：SSH 登录服务器

在轻量应用服务器控制台点击 **"登录"**（网页终端即可），或者本地用 SSH：

```bash
ssh root@你的服务器公网IP
```

### 第二步：运行一键部署脚本

```bash
bash <(curl -sSL https://raw.githubusercontent.com/oceancat91/social-sense/main/deploy/tencent-cloud/setup.sh)
```

脚本会自动完成：
1. 安装 Docker + Docker Compose
2. 克隆项目代码
3. 生成强随机密钥和数据库密码
4. 构建 Docker 镜像并启动所有服务
5. 等待数据库就绪后灌入演示数据

整个过程约 5-8 分钟。

### 第三步：访问

部署完成后脚本会输出：

```
访问地址:  http://你的服务器IP/app/
登录邮箱:  admin@social-sense.com
登录密码:  admin123
```

## 手动部署（分步执行）

如果不想用一键脚本：

```bash
# 1. 安装 Docker
curl -fsSL https://get.docker.com | bash

# 2. 克隆项目
git clone https://github.com/oceancat91/social-sense.git
cd social-sense

# 3. 创建配置
cp deploy/tencent-cloud/.env.example config/.env
# 编辑 config/.env，修改 DB_PASSWORD 和 APP_SECRET_KEY
# 生成密钥：python3 -c "import secrets; print(secrets.token_hex(32))"
# 可选：配置 LLM_API_KEY 以启用 LLM 情感分析
# 可选：配置 DEEPSEEK_API_KEY 以启用多 Agent 的 LLM 结论生成与主控归纳
# （未配置时自动降级为确定性规则，仍可跑通跨平台融合）

# 4. 启动所有服务
docker compose --env-file config/.env -f deploy/docker-compose.yml up -d --build

# 5. 灌入演示数据（脚本可幂等重跑）
# 路径相对 backend 容器 WORKDIR=/app，对应仓库 backend/scripts/seed_demo.py
# 本地开发请改用：python scripts/bootstrap/seed_demo.py
docker compose --env-file config/.env -f deploy/docker-compose.yml exec -T backend python scripts/seed_demo.py
```

## 常用运维命令

```bash
# 查看服务运行状态
docker compose --env-file config/.env -f deploy/docker-compose.yml ps

# 查看实时日志
docker compose --env-file config/.env -f deploy/docker-compose.yml logs -f backend

# 重启某个服务
docker compose --env-file config/.env -f deploy/docker-compose.yml restart frontend

# 停止所有服务
docker compose --env-file config/.env -f deploy/docker-compose.yml down

# 重新构建并启动
docker compose --env-file config/.env -f deploy/docker-compose.yml up -d --build
```

## 正式域名双站点部署（可选）

需要同时提供 Landing 和分析台时，使用仓库内的
`deploy/nginx-social-sense.conf`：

- `/` → Next.js Landing（`127.0.0.1:3100`）
- `/app/` → `frontend/dist` 静态分析台
- `/api/`、`/health` → Flask 后端（`127.0.0.1:5000`）

```bash
# 构建两个前端
npm --prefix landing ci
npm --prefix landing run build
npm --prefix frontend ci
npm --prefix frontend run build

# 按实际域名、证书和仓库路径调整配置后启用
sudo cp deploy/nginx-social-sense.conf /etc/nginx/sites-enabled/social-sense
sudo nginx -t
sudo systemctl reload nginx
```

该配置属于宿主机进程拓扑，不与 Compose 的 `frontend` 容器混用。
Landing 需通过 systemd、PM2 或其他进程管理器持续运行
`npm --prefix landing run start`。

## 架构总览

```
用户浏览器
    │
    ▼
┌──────────────────────┐
│  腾讯云防火墙 (80)     │
└──────────┬───────────┘
           ▼
┌──────────────────────┐
│  frontend (Nginx:80) │  ← 静态页面 + API 反向代理
└──────────┬───────────┘
           ▼ /api/*
┌──────────────────────┐
│  backend (Flask:5000)│  ← 业务逻辑 + NLP 分析 + 多 Agent 引擎
│   ├─ agent/          │     单平台 Skill1–6（只读挂载）
│   └─ multiagent/     │     跨平台对齐·融合·茧房指数
└──────┬───────┬───────┘
       ▼       ▼
┌──────────┐ ┌──────┐
│  MySQL   │ │Redis │  ← 数据持久化
│  :3306   │ │:6379 │
└──────────┘ └──────┘
```

所有服务跑在同一台服务器上，通过 Docker 内部网络通信，MySQL 和 Redis 端口不暴露到公网。

## 多 Agent 引擎配置与验证

### 关键环境变量

| 变量 | 必填 | 说明 |
|------|------|------|
| `LLM_API_KEY` | 否 | 启用 LLM 情感分析；未配置时回退到本地模型或词典 |
| `LLM_BASE_URL` | 否 | OpenAI 兼容接口，默认 `https://api.deepseek.com` |
| `LLM_MODEL` | 否 | 情感分析模型，默认 `deepseek-chat` |
| `DEEPSEEK_API_KEY` | 否 | 启用 Skill5/6 结论生成与主控归纳的 LLM；未配置自动降级为确定性规则 |
| `DEEPSEEK_MODEL` | 否 | 默认 `deepseek-chat` |
| `AGENT_ROOT` | 否 | agent 代码目录，容器内默认 `/app/agent` |
| `MULTIAGENT_ROOT` | 否 | multiagent 代码目录，容器内默认 `/app/multiagent` |
| `AGENT_OUTPUT_DIR` | 否 | 引擎中间产物目录（知识库 / 隐状态），默认 `/app/agent_outputs`（已挂卷持久化） |

### 数据源说明

后端采集服务（`CrawlerService`）按平台自动选择数据源：

- **真实采集（可选）**：配置了平台 cookie 时，通过 `agent/PlatformCrawler` 的真实采集适配器（bilibili/weibo/douyin/xiaohongshu/zhihu/kuaishou）采集真实舆情，经清洗 + 情感分析后写入 `SentimentData`。
- **模拟数据（默认）**：未配置 cookie 或采集失败时，自动回退到 mock 数据源，保证无凭证环境仍可端到端演示。

多 Agent 引擎本身**不直接跑爬虫**，而是把后端 `SentimentData` 转成标准 `D_platform` 契约后跑 Skill2–6 与跨平台融合，因此上述两种数据源对引擎完全透明。

#### 配置真实采集（可选）

真实采集需为每个平台配置登录 cookie，文件位置（以仓库根目录为基准）：

| 平台 | cookie 文件路径 |
|------|----------------|
| B站 | `agent/PlatformCrawler/crawler/bili_cookie.txt`（可选 `bili_ua.txt`）|
| 微博 | `agent/PlatformCrawler/adapters/weibo_cookie.txt` |
| 抖音 | `agent/PlatformCrawler/adapters/douyin_cookie.txt` |
| 小红书 | `agent/PlatformCrawler/adapters/xiaohongshu_cookie.txt` |
| 知乎 | `agent/PlatformCrawler/adapters/zhihu_cookie.txt` |
| 快手 | `agent/PlatformCrawler/adapters/kuaishou_cookie.txt` |

- B 站可用 `python agent/PlatformCrawler/crawler/auto_get_cookie.py` 半自动获取 cookie；
- 其余平台需在浏览器登录后，从开发者工具复制 Cookie 请求头到对应文件。
- 这些 cookie 文件已被 `.gitignore` 忽略，不会提交到仓库。

配置 cookie 后，创建监控任务即自动走真实采集：

```bash
# 创建监控任务（auto_collect=true 默认触发采集）
curl -s http://服务器IP/api/v1/tasks -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"platform":"bilibili","keywords":["校园食品安全"],"days":14}'

# 等任务状态变 active（data_count > 0），再创建多 Agent 分析任务
curl -s http://服务器IP/api/v1/agent/analyze -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"keyword":"校园食品安全","platforms":["bilibili","weibo"]}'
```

### 部署后验证

```bash
# 1. 登录获取 token
curl -s http://服务器IP/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"admin@social-sense.com","password":"admin123"}'

# 2. 探测引擎可用性（返回 available: true 即部署成功）
curl -s http://服务器IP/api/v1/agent/status -H 'Authorization: Bearer <token>'

# 3. 创建跨平台分析任务（需已有采集任务数据，或先用 seed 灌数据）
curl -s http://服务器IP/api/v1/agent/analyze -H 'Authorization: Bearer <token>' \
  -H 'Content-Type: application/json' \
  -d '{"keyword":"校园食品安全","platforms":["bilibili","weibo"]}'

# 4. 查看报告（status=success 后，result.cross_platform 含茧房指数）
curl -s http://服务器IP/api/v1/agent/reports -H 'Authorization: Bearer <token>'
curl -s http://服务器IP/api/v1/agent/reports/1 -H 'Authorization: Bearer <token>'
```

### 排障

```bash
# 查看后端日志（含 agent 引擎加载/降级信息）
docker compose --env-file config/.env -f deploy/docker-compose.yml logs -f backend

# 引擎不可用（available: false）时，确认 agent/、multiagent/ 目录已随代码仓库克隆到位
ls -d agent multiagent
```
